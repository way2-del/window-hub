# 窗口吸色的杂色降级

窗口 edge 模式在现有捕获、映射完成后调用 `win32/ambient_policy.rs`。只分析最终顶栏色带（最多 1280 个 RGB 像素），不增加捕获频率、系统调用、线程或锁。壁纸和 center 模式保持原有行为。

相邻像素任一通道相差至少 24 视为强边缘；至少出现 12 次且占相邻像素对的 4% 时，认为色带过于零碎。平滑渐变、纯色、少数宽分区保留原样。RGB 每通道量化为 16 档，从 4096 个桶中选择覆盖最多的颜色组，并使用该组原始颜色均值作为纯色。相同票数固定选择索引较小的桶，保证确定性。

这是对采样色带的启发式判断，不是文字识别，也不代表整幅窗口图像的最大面积。低对比度文字、稀疏文字可能不会触发；密集装饰条纹也会降级。阈值有意保留低对比度变化。

降级沿用现有 AmbientStrip DTO：width=1，r/g/b 和 PNG 使用同一颜色，span_width、hwnd、mode 保持原语义。前端 App 的背景和左右/中部文字对比度都走现有纯色分支；没有新增 IPC、设置键或 CSS token。

成本是两次有界像素遍历和 4096 桶扫描，固定 8 KiB 栈空间，无堆分配。2026-09-24 本机优化编译的 100000 次最宽色带测试平均约 5.62 微秒/次，仅代表策略计算，不含截图、编码、传输和渲染，不构成整个应用性能保证。

策略自带单元测试，覆盖渐变、分区、文字笔画、杂色主色、近似色均值、输入边界和低对比噪声。`timing` 是默认忽略的手动优化编译计时测试。

## 切换响应与过渡

后台 watcher 每 80ms 只读取前台 HWND；最大化 / 桌面目标变化时提前执行取色流程。工作区 quiet 保护和截图超时继续有效。捕获期间前台发生变化则丢弃旧结果。这里的 80ms 是检测间隔，不是完整取色延迟保证。

切换目标后 **live 采样约 2 秒**（`SETTLE_MS`），随后 **锁定色带**：同一最大化窗口内切标签 / 页面导航不再刷新。仅当出现**新的最大化 / 全屏目标**，或**回到桌面**（无最大化目标）时解锁并重新 settle。壁纸路径在锁定后同样保持缓存。

**副屏 `chrome-sat-*`** 使用独立的 per-label gate（`poll_changed_sat`），策略与主屏相同：2 秒 settle → lock → 仅目标切换解锁；不与主屏 `GATE` 共用，避免交叉抖动。

App 仅使用 `features/chrome/AmbientStrip.tsx` 呈现双层色带，以 160ms opacity 动画覆盖旧色带，适用于纯色和 PNG。最多保留两层，不使用逐帧 React 状态更新；快速更新替换目标，不积压动画。遵循 prefers-reduced-motion。桌面与窗口间的原生玻璃材质切换不在此动画范围内。
